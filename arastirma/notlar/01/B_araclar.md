## PART 1: Hobbyist / worldbuilder tectonic and planet simulators

### 1. The GeoChronicler (Noossablue)
- What: "An interactive tectonic plate editor for simulating geological history." A browser app (React + HTML5 Canvas) where you **draw** plates, continents, cratons, orogens, LIPs, rifts, ocean segments, island arcs and hotspots on a 3D globe and keyframe them as **snapshots** in Mya (0–1000 Mya). Inspired by the Worldbuilding Pasta "Apple Pie from Scratch" series and by GPlates.: https://geochronicler.netlify.app/ (meta description), https://geochronicler.netlify.app/instructions.md
- Plate motion over time: yes, but **manual/kinematic**: "you manually position plates rather than simulating mantle convection"; "Interpolation between snapshots is linear". "Plate spreading" means frozen spreading edges stay fixed while the plate is dragged away. Subduction does not consume area automatically ("you manage this manually"). Velocities shown in cm/yr come from centroid displacement between snapshots.: https://geochronicler.netlify.app/instructions.md
- Topography from collisions: **no elevation/heightmap at all**. Collision is done manually: "The GeoChronicler doesn't simulate collision physics automatically"; the user draws an orogen polygon along the suture and later marks it inactive.: https://geochronicler.netlify.app/instructions.md
- Erosion: none (no elevation model).: same
- Start from a present-day coastline: no image/mask import. You can draw continents as polygons at 0 Mya and work backwards by snapshots (the timeline runs 0→1000 Mya and the user can edit any time). Continents can be "locked". No automatic reconstruction.: same
- Export: project JSON (plates, continents, features, snapshots, hotspots, shared rifts…; schema documented), PNG map (Equirectangular / Mollweide / Robinson, adjustable center longitude), animated GIF (timelapse needs ≥2 snapshots), PDF via the print dialog, docs as Markdown.: https://geochronicler.netlify.app/instructions.md ; UI strings in the JS bundle https://geochronicler.netlify.app/assets/index-Dir9pyDj.js ("Export Map (PNG)", "Export Project (JSON)", "Export Animation", "Generating GIF...")
- License: proprietary, "© 2026 Noossablue. All rights reserved."; free to use (Buy-me-a-coffee link). Browser only; not for mobile/touch screens; data stored in localStorage.: https://geochronicler.netlify.app/instructions.md
- Version: bundle contains a "0.1.1" string (likely the app version; UNVERIFIED that it is). Last update: UNVERIFIED (the changelog.md route returns a 404 HTML page; the Notion page https://noossablue.notion.site/The-GeoChronicler-31890855e69780d2b36efa5fc43e2822 needs JavaScript and could not be read).
- Relevance: a good model for a **plate-history data model** (plate hierarchy, edge types, snapshots as JSON), but it produces no relief.

### 2. Tectonics.js (Carl Davidson, davidson16807)
- What: "a 3d plate tectonics simulator written in javascript", in the browser, about 10,000 grid cells.: https://davidson16807.github.io/tectonics.js/blog ; https://github.com/davidson16807/tectonics.js (README)
- Plate motion: yes, **emergent**. It tracks oceanic crust age → density → subduction when density passes a threshold; velocity fields point toward subducting regions; plates are found by image segmentation of the velocity field; gaps are filled by new crust (ridges).: https://davidson16807.github.io/tectonics.js/blog
- Topography/mountains: simulated mountains through crust accretion. Before erosion was added they "eventually occupy every available cell of continental crust".: repo _posts/2014-1-29-reddit-erosion-photosynthesis.md (https://github.com/davidson16807/tectonics.js/tree/master/_posts)
- Erosion: yes, a large-scale model based on Simoes et al. 2010 (research/simoes2010.pdf). Erosion rate is "a fraction of height per unit of precipitation". The author admits calibration problems (mountain height overpredicted, coasts too rounded).: same post
- Fixed coastline / reconstruction: no. Starts from fractal initialization.: blog FAQ "Why not use fractals? We do, for initialization"
- Export: equirectangular screenshot/texture export; save files (~170 KB JSON, "no guarantees on forward compatibility").: _posts/2015-5-17-save-and-export.md
- License: **conflicting statements**. The blog page says both "version 2.0 of the Creative Commons Non Commercial Attribution License" and "version 4.0 of the Creative Commons Attribution license"; the repo LICENSE.txt is "Attribution 4.0 International" (CC BY 4.0).: https://davidson16807.github.io/tectonics.js/blog ; repo LICENSE.txt
- Last update: last commit on master 2020-08-22 ("Merge pull request #60"); last blog post 2019-08-04. Effectively dormant.: git log of https://github.com/davidson16807/tectonics.js
- Platform: web browser; free.

### 3. PlaTec / plate-tectonics (Mindwerks; Lauri Viitanen original)
- What: C++ library (with **Python bindings, `pip install PyPlatec`**) "to simulate plate tectonics", producing heightmaps; a fork of SourceForge platec, from a Bachelor's thesis at Metropolia UAS (Viitanen 2012).: https://github.com/Mindwerks/plate-tectonics (README)
- Plate motion: yes, a 2D (rectangular, wrap-around) lithosphere with N plates, collision/aggregation (`aggr_overlap_abs`, `aggr_overlap_rel`), `folding_ratio`, `cycle_count`. API: `platec.create(seed,width,height,sea_level,erosion_period,folding_ratio,aggr_overlap_abs,aggr_overlap_rel,cycle_count,num_plates)`, `step`, `is_finished`, `get_heightmap`, `get_platesmap`, `get_agemap`, velocity per plate.: README; src/platecapi.hpp
- Topography: mountains from crust folding/collision (heightmap output).: README
- Erosion: simple periodic erosion (`erosion_period`); changelog 1.4.4 clamps heightmap after erosion.: changelog.txt
- Start from user land mask: **no**: `platec_api_create` takes only scalar parameters (no initial heightmap argument).: src/platecapi.hpp
- Export: in-memory float heightmap/plates/age arrays; the C++ example writes PNG (needs libpng).: README
- License: LGPL-3.0 (LICENSE). Version 1.4.4 (pybindings/pyproject.toml); wheels for Python 3.9–3.14 (changelog 1.4.3). Last commit 2025-11-23 ("Linting, formatting and ubsan fixes (#55)"). Linux/macOS/Windows via CMake.: repo
- Used by WorldEngine and the Widelands map "Lost Islands".: README
- Relevance: runs headless on Linux in Python → **usable on GitHub Actions**, but it cannot be constrained to a given coastline.

### 4. WorldEngine (Mindwerks)
- What: "the best open-source world generator", based on simulations of several physical phenomena; usable from the CLI, a GUI or as a library; meant to sit in a tool-chain ("you give some draft of your world to WorldEngine, it performs some extra simulations").: https://worldengine.readthedocs.io/en/latest/
- Plate motion: uses PyPlatec (plates step). Operations: `world|plates|ancient_map|info|export`.: https://github.com/Mindwerks/worldengine worldengine/cli/main.py
- Topography: from platec; then hydrology/erosion: "River and its erosion are now taken into account" (v0.18); simulations: erosion, hydrology, precipitation, temperature, humidity, permeability, irrigation, icecap, biome.: CHANGELOG.md; worldengine/simulations/
- Fixed coastline: **no import of a draft heightmap/mask in the CLI** (options are only seed, width/height, number of plates, ocean level, etc.). The docs' "give some draft" statement is aspirational; UNVERIFIED that any import path exists.: cli/main.py argument list
- Export: 16-bit grayscale PNG heightmap (v0.19), HDF5 / protobuf world files, and GDAL export (`--export-format envi --export-datatype float32`, any GDAL format).: CHANGELOG.md; worldengine/imex/__init__.py
- License: MIT. Version 0.20.0 (worldengine/version.py), Python ≥3.10 (pyproject), up to Python 3.14. Last commit 2026-11-03 (dependabot merge #292): maintained mostly as dependency upkeep.: repo
- Platform: Python, Linux-friendly, Dockerfile present → **GitHub Actions friendly**.

### 8. Red Blob Games: planet generation (2018) and mapgen4
- 1843 planet generation: a 9-day experiment on a Fibonacci-sphere Delaunay/Voronoi mesh; random plates by random fill; random plate direction vectors; boundary rules (land+land converging → mountain; land+ocean → mountain/coastline) with a 0.75 threshold; interior elevation by interpolating 3 distance fields; rivers from the mapgen4 code. No time evolution and no real erosion. Author: "Mountains don't look right". Follows Andy Gainey's approach.: https://www.redblobgames.com/x/1843-planet-generation/
  - License Apache-2.0; "unmaintained" badge; last commit 2026-03-29 (added plate-tectonics links).: https://github.com/redblobgames/1843-planet-generation
- mapgen4: paint mountains/valleys/oceans, then it simulates evaporation, wind, rainfall → biomes and rivers; elevation from distance fields (not tectonics or erosion); "Status: Finished … mostly inactive", but 2024–2025 rewrites (renderer, rivers, `mountain_folds` slider). "Everything you create with it is yours".: https://www.redblobgames.com/maps/mapgen4/ ; code Apache-2.0, last commit 2026-03-29 https://github.com/redblobgames/mapgen4
- Coastline is painted by the user (not imported). No tectonics over time.

### 12. TileTectonics (gusevans)
- A toy grid simulator: rectangular plates on a wrap-around grid move one step; conflicts (red) and gaps (grey) are resolved by neighbor-majority rules (conflicts prefer continental, gaps prefer oceanic). No elevation/erosion. "This simulation is in no way realistic… plates tend to reach an equilibrium". Map codes for replay. Last commit 2021-01-15; no LICENSE file.: https://gusevans.github.io/TileTectonics ; https://github.com/gusevans/TileTectonics

### 13. Experilous procedural planet generator (Andy Gainey, 2014–2016)
- Subdivided icosahedron, distorted for irregular tiles; plates by random flood fill; each plate gets a rotation axis + rate (drift) and spin, an oceanic/continental flag and a desired elevation; boundary **pressure** (normal component) and **shear** (tangential) → elevation rules (same type colliding → max+mountain range; ocean vs land → subduction profile; separation/shear → weaker raise); interior by a priority queue that blends boundary-distance and center-distance curves. Then air currents → heat → moisture (rain shadow) → biomes. No time evolution and no erosion.: https://icewyrmgames.github.io/examples/procedural-planet-generation (copy of "Procedural Planet Generation", Andy Gainey, May 11 2016; original experilous.com URL could not be fetched; archived at web.archive.org/web/20220617041817/http://experilous.com/1/blog/post/procedural-planet-generation: not read)
- License of the generator code: UNVERIFIED.

## Key takeaways for a tool that keeps a fixed coastline, invents a tectonic history and produces realistic eroded relief, running Python on GitHub Actions

1. **No existing tool does the whole job.** None of the tools found takes a present-day land mask, keeps it fixed and *infers* a plausible plate history plus relief. Gleba comes closest (outline import + plate direction markers + orogenies + erosion), but it is a closed GUI app for Windows/Linux and does not guarantee a fixed coastline (UNVERIFIED). GeoChronicler supports manual backward reconstruction but has no relief. → Building our own is justified. (sources: Gleba itch/devlogs; GeoChronicler docs)
2. **Only open-source Python/C++ options run headless on ubuntu runners:** PyPlatec (LGPL-3.0, `pip install PyPlatec`, wheels for 3.9–3.14) and WorldEngine (MIT). Neither accepts an initial land mask, so they are useful only as references or as noise sources. Their algorithms (Viitanen's lithosphere: plate collision → crust folding and aggregation; periodic erosion) can be ported. LGPL is fine for linking, but copying code into an MIT project is not. (Mindwerks repos)
3. **Commercial erosion engines don't fit CI:** Gaea and World Creator are Windows/GPU-licensed; Instant Terra is Windows-only and dormant; Wilbur is Windows freeware with no CLI. World Machine (native Linux AppImage since Build 4065, XML command-line automation in Pro $299) and Houdini (Linux, command-line in all editions incl. free Apprentice, which is non-commercial) are the only ones that could *technically* run on Linux CI, and both need licenses, installs of several GB and probably an X server (UNVERIFIED). They are better used as optional offline post-processors than as a dependency.
4. **The "tectonic" nodes in pro tools are shape filters** (Gaea Uplift/Fold/Shear/Stratify, WM Strata), not plate models. Tectonics must come from our own model: Gainey-style boundary stress (normal = pressure, tangential = shear) → uplift profiles is the simplest proven recipe; Red Blob's version adds a collision threshold (0.75) to avoid mountains on every boundary; Tectonics.js shows emergent age → density → subduction. (icewyrmgames mirror; Red Blob; Tectonics.js blog)
5. **Continental-scale realism:** practitioners say Gaea struggles with mountain ranges near its practical ~2,400 km maximum and that Wilbur gives nicer large-scale erosion (Kilroy's Kartography, 2025-10-01; the 2,400 km figure is not in official Gaea docs). Wilbur's recipe maps directly to Python: **priority-flood Fill Basins → absolute noise ~5 % of max height → Fill Basins → flow-accumulation incision with an exponent (stream-power-like) → Fill Basins → a light particle ("precipiton") erosion pass**. The author warns that raw incise flow is "hydrologically implausible" without the follow-up passes. (ProFantasy forum, jslayton 2020; Astrographer; PMC wiki)
6. **Keeping the coastline fixed** is done everywhere with masks: Houdini Erodability Mask, Gaea masks / Sea node, WM selectors, Wilbur height-range selections, Instant Terra masks that "protect some areas". For us: clamp land cells ≥ a small positive height and ocean cells < 0 after every erosion/uplift step, and use the ocean as the fixed base level (outlet) for flow routing, so drainage always ends at the given coast. Coastal-erosion nodes (Gaea Sea, WM Coastal Erosion) move the shore and should be off or masked.
7. **Output conventions to match:** a 16-bit PNG/GeoTIFF heightmap with an explicit meters scale (Cartogenesis, WorldEngine), 32-bit float EXR/TIFF for pro import (Gaea, WM, Houdini), and a separate land/sea mask (Nixis). A square tile at ≤2,400 km helps users who will finish in Gaea. Equirectangular output for whole planets needs latitude-aware cell areas, which most flat-terrain erosion tools ignore (Nixis README).
8. **Data model inspiration:** GeoChronicler's JSON (plates → continents → cratons/orogens/LIPs, edge types: spreading/subduction over-under/transform, snapshots in Mya) is a clean schema for recording an invented tectonic history that a later relief step can read (active vs inactive orogens → young high vs old worn mountains; LIPs → plateaus). (GeoChronicler instructions.md)
