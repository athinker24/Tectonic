**Fitness (Fastscapelib):** Best fit for "keep the present-day coastline": per-node FIXED_VALUE base levels on the coast plus GHOST/masked ocean, exactly as in the planetary example. Its implicit O(n) SPL with MST or priority-flood sink resolution is fast and serial, so it is GitHub-Actions-friendly. PyPI wheels lack HealpixGrid; use conda-forge for a global Healpix grid, or use RasterGrid/TriMesh (pip) over the continent box. It has only detachment-limited SPL plus raster-only linear diffusion: no sediment deposition, flexure, plate advection or climate. Uplift from the invented block history must be supplied as a per-node rate array each step. Development has been quiet since June 2025.

**Fitness (goSPL):** The only tool here built exactly for global, spherical, plate-advected landscape evolution with sediment routing, marine deposition and global flexure, and it is actively maintained (commits in Nov 2026). But it is heavy: MPI+PETSc+parallel-HDF5, sdist-only on PyPI, so on GitHub Actions use the `geodels` conda channel (or the Docker image). It does not create plate histories or meshes itself. You supply per-node `hdisp`/`upsub` .npz fields (e.g. from your own block rotations) plus a jigsaw/stripy mesh. Memory sets the limit: the 10 km global mesh needs >=16 ranks at ~6.6 GB each, so a 16 GB / 4 vCPU runner realistically means a ~25-35 km global mesh (0.5-1M nodes, my estimate, UNVERIFIED), or a 2D regional mesh over the continent box. Orographic rain works only in 2D models. A fixed coastline is not native, because the coast is wherever elevation crosses sea level. Workarounds: the undocumented `zfit` step, which resets nodes below sea level to a target field at interval ends; or re-imposing ocean elevations or uplift between restarts. On a 2D regional mesh, walls/fixed edges set the boundary.

**Fitness (pyGPlates/GPlately):** Good for the plate-history half. You can write a synthetic rotation file (.rot) and polygons for invented blocks and get rotations, velocities at mesh nodes (`get_point_velocities`), and reconstructed rasters. Then convert to goSPL `hdisp`, or into uplift fields where blocks converge. Both are pip wheels, so Actions-friendly, but GPL-2. They do not make elevation: you must turn plate kinematics into topography yourself (collision -> uplift rules, rifts -> subsidence). Because the present-day coastline is fixed, you can run the history "forward to present" while forcing final block positions to match the mask, or simply use kinematics only to place sutures/orogens inside a fixed mask.

**Fitness (paleo-DEM tools):** No turnkey, headless, pip-installable "plate model -> paleo-DEM" generator exists. Utrecht's calculator is unreleased, TopoChronia and Terra Antiqua are QGIS GUI plugins tied to PANALESIS or real DEMs, and Scotese's maps are hand-made. The transferable ideas are the rule sets: ocean depth from age (Stein & Stein); continental elevation from crustal thickness + Airy isostasy; setting-specific templates for arcs, orogens, rifts and margins. Your own Python generator can apply them to invented blocks inside the fixed mask. The fixed coastline is fully under your control because you write the elevation rules.

**Fitness (Badlands):** It is a 2D regional predecessor of goSPL by the same author (T. Salles), with maintenance releases only (a 2026 packaging release after a 2.5-year gap) and pinned to numpy<2. It could model the continent box with sea level and marine deposition, but it does not hold a coastline fixed. It brings no advantage over goSPL 2D or Landlab, and the numpy<2 pin makes modern environments harder. Not recommended.

## Key takeaways
1. Runner budget: public repo = 4 vCPU/16 GB, private = 2 vCPU/8 GB, 6 h per job (docs.github.com). Global goSPL at Salles-style 5-10 km resolution needs HPC (16-168 ranks, 6.6-24 GB per heavy rank). It is not feasible on Actions. Only coarse (~25-35 km) global or regional 2D runs fit.
2. No tool generates paleo-DEMs from an invented plate history out of the box. Salles et al. drive goSPL with hand-made PALEOMAP PaleoDEMs + GPlates velocities and "nudge" (assimilate) toward them. For a fictional world, the PaleoDEM step must be our own rule-based generator: isostasy/crustal thickness, age-depth, orogen templates.
3. The fixed present-day coastline is easiest in Fastscapelib (FIXED_VALUE + GHOST nodes; the Healpix planetary example does this) and Landlab (boundary status). goSPL lets the coastline evolve with sea level and erosion/deposition. Only the undocumented `zfit` reset or a 2D domain with walls/fixed edges approximates it.
4. Practical stack: pyGPlates/GPlately (or plain numpy Euler rotations) for block kinematics -> own uplift/crust-thickness field inside the fixed mask -> Fastscapelib (pip, fast SPL, MST/priority-flood sinks; RasterGrid or TriMesh over the continent box) or Landlab (SPACE for sediment) for erosion. goSPL is optional for a coarse global or 2D regional run via the conda `geodels` channel if marine deposition, flexure or orographic rain are wanted.
5. Licensing: Fastscapelib, goSPL and Badlands are GPL-3, pyGPlates and GPlately GPL-2, Landlab MIT. That matters only if the pipeline code is distributed.
